# 🚀 PM2 進程管理、日誌與維護指南

PM2 是一款專業的 Node.js 進程管理器，它能確保應用程式在崩潰後自動重啟，並在系統開機時自動執行。

---

## 🛠 一、 基礎進程管理 (入門必備)

在進行進程恢復前，必須先了解如何正確啟動應用程式。

### 1. 啟動應用程式

```bash
# 最基本的啟動方式 (給予明確名稱方便後續管理)
pm2 start app.js --name "my-app"

# 啟動並在檔案變動時自動重啟 (開發環境常用)
pm2 start app.js --watch

```

### 2. 狀態查看與控制

| 功能 | 指令 |
| --- | --- |
| **查看所有進程清單** | `pm2 list` |
| **查看特定進程詳情** | `pm2 show [ID/Name]` |
| **重啟 (零停機時間)** | `pm2 reload [ID/Name]` |
| **停止進程** | `pm2 stop [ID/Name]` |
| **刪除進程** | `pm2 delete [ID/Name]` |

---

## 🔍 二、 日誌管理 (排查錯誤)

當應用程式運作異常時，日誌是唯一的線索。

### 1. 查看日誌

* **即時監看所有進程**：`pm2 logs`
* **指定進程日誌**：`pm2 logs [Name/ID]`
* **查看歷史最後 100 行**：`pm2 logs --lines 100`

### 2. 找回消失的進程名稱

如果你忘記之前的 `name`，直接查看 PM2 儲存日誌的資料夾，檔案名稱的開頭就是你之前的進程名稱：

```bash
ls ~/.pm2/logs/

```

### 3. 清理日誌

PM2 的日誌檔案若太久沒清會佔用大量硬碟空間。

```bash
# 清空目前所有日誌內容
pm2 flush

```

---

## 🚑 三、 進程恢復與故障修復

當執行 `pm2 save` 出現 `[WARN] PM2 is not managing any process` 時，代表記憶體中的列表已空，需從硬碟找回。

### 1. 恢復最後一次存檔 (Resurrect)

如果你以前曾執行過 `pm2 save`，這個指令會從硬碟讀取快照並重新啟動所有進程。

```bash
pm2 resurrect

```

### 2. 永久保存目前的清單 (關鍵！)

當你手動修正了進程，或新啟動了服務，務必執行此指令，否則伺服器重啟後設定會遺失。

```bash
pm2 save

```

### 3. 設定開機自動啟動 (補充重點)

即使 `pm2 save` 了，若沒有設定系統服務，主機重啟後 PM2 也不會運作。

```bash
# 1. 產生開機啟動腳本
pm2 startup

# 2. 複製終端機出現的提示指令並執行 (通常是 sudo env PATH=...)

# 3. 最後再存檔一次
pm2 save

```

---

## 💡 四、 常見操作流程總結

| 場景 | 操作步驟 |
| --- | --- |
| **首次部署** | `pm2 start app.js --name web` -> `pm2 save` -> `pm2 startup` |
| **更新程式碼** | `git pull` -> `pm2 reload web` |
| **伺服器重啟後進程消失** | `pm2 resurrect` |
| **更換進程名稱** | `pm2 delete old-name` -> `pm2 start app.js --name new-name` -> `pm2 save` |

---

> **專業建議：** 建議安裝 `pm2-logrotate` 插件，讓 PM2 自動幫你壓縮並切割舊日誌，防止硬碟爆滿：
> `pm2 install pm2-logrotate`
